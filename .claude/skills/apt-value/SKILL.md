# 단지 가치 분해 (apt-value)

특정 **아파트 단지 하나**를 깊게 본다. 두 데이터를 합친다:
- **국토부 공동주택 기본정보 API** → 세대수·동수·준공(연식)·주차·난방·복도유형 등 '단지 스펙'
- **국토부 실거래가(매매)** → 같은 단지 안에서 동별·층별·평형별 '가치'

핵심 질문: *이 단지는 어떤 단지이고, 그 안에서 어느 동·어느 층·어느 평형이 값을 더 받는가?*

산출물은 사용자 프로젝트 폴더 안 `aptvalue_<단지>/`에 모은다.

## 데이터 경계 (먼저 알 것)

- **향(방향)은 어떤 공공데이터에도 없다.** 실거래엔 층·동명만 있고 향·호가 없다. 그래서 이 스킬은
  향을 다루지 않는다. 사용자가 원하면 동→향 매핑을 받아 근사할 수 있지만 기본은 제외.
- 실거래 `아파트동명`은 약 2/3만 채워져 있어 동별 분석은 동명 있는 거래만 대상이다.
- 공동주택 API는 실거래와 **별개 활용신청**이 필요하다 → `references/api.md`. 미신청이면 403이 뜨고,
  이때는 세대수·동수 없이 실거래 기반(연식은 실거래 건축년도) 분석만 나온다.
- **일부 시군구(실측: 화성시)는 목록 API가 `totalCount=0`(데이터 공백)** 이라 이름검색이 안 된다.
  `fetch_complex.py`가 시도목록으로 자동 우회하지만, 그래도 없으면 `--kapt-code` 직접 지정이 필요하다.
  경매 후보를 대량 스크리닝할 땐 **시도목록 1회 캐시 후 로컬 매칭**이 정석(`references/api.md`).

## 워크플로

준비: `.env`에 `PUBLIC_DATA_SERVICE_KEY`(Decoding 키). venv에 PublicDataReader≥1.1.1, pandas,
python-dotenv, requests, xmltodict, playwright 설치(realprice-flow의 setup.sh와 동일 환경 재사용 가능).

### 1. 실거래 매매 수집 (해당 단지의 시군구)
단지가 속한 시군구의 매매를 최근 2~3년 모은다(단지 필터는 분석 단계에서). 이미 realprice-flow로
그 구의 `sale.csv`가 있으면 그걸 그대로 workdir에 두고 재사용하면 된다. 없으면 월별로 수집:
```python
# collect: pdr.TransactionPrice(key).get_data(property_type='아파트', trade_type='매매',
#          sigungu_code=코드, year_month=YYYYMM, verbose=False) 를 월별로 append.
# verbose=True 금지(한글 DataFrame 출력 시 세그폴트). realprice-flow/scripts/collect.py 재사용 권장.
```

### 2. 단지 프로파일 (세대수·동수·연식) — 공동주택 기본정보 V4(JSON)
```bash
python scripts/fetch_complex.py --name 도곡렉슬 --district 강남구 --workdir aptvalue_도곡렉슬
# kaptCode를 이미 알면 목록 서비스 없이 바로:
python scripts/fetch_complex.py --kapt-code A13586103 --workdir aptvalue_도곡렉슬
```
`complex_profile.json` 생성. **두 서비스 활용신청이 필요**하다(`references/api.md`):
기본정보 V4(세대수·동수)와 목록 서비스(단지명→kaptCode). 목록 서비스가 403이면 이름 검색이 막히니
kaptCode를 직접(`--kapt-code`, k-apt.go.kr에서 확인 가능) 주거나 사용자에게 목록 서비스 활용신청을 안내한다.
기본정보까지 403이면 이 단계를 건너뛰고 3~4만 진행한다(리포트가 세대수 자리를 비우고 안내 문구를 넣음).

### 3. 동·층·평형 가치 계산
```bash
python scripts/analyze_value.py --workdir aptvalue_도곡렉슬 --name 도곡렉슬 --district 강남구 --months 24
```
`complex_value.json` 생성. 방법론: 평형(전용면적) 효과를 먼저 제거한 뒤(같은 면적대 평균 대비 편차),
그 편차를 동·층으로 모아 순수 '동 프리미엄'·'층 프리미엄'을 뽑는다. complex_profile.json이 있으면 병합.
같은 단계에서 최근 6개월치 원거래도 `recent`로 함께 저장한다(표본 5건 미만이면 생략).

### 4. 리포트 생성 + 검증
```bash
python scripts/build_report.py --workdir aptvalue_도곡렉슬
```
`report.html`(로컬) + `report_artifact.html`(Artifact용) 생성. 01 평형별 시세 · 02 동의 가치 ·
03 층의 가치에 이어 **04 최근 흐름**(최근 6개월 실거래 가격 점도표, 전용면적 3분위로 색 구분)이
`recent` 데이터가 있으면 자동으로 붙는다. **playwright 헤드리스 스크린샷으로
렌더 확인**(콘솔 print 금지 — 한글 DataFrame 세그폴트). 그다음 Artifact로 발행해 공유 링크를 준다.

## 결과 전달

먼저 핵심을 말한다: 단지 스펙(세대수/연식/동수), 가장 비싼 동과 가장 싼 동의 차이(%p), 평형별 시세 범위.
"같은 단지라도 동에 따라 N%p 벌어진다" 같은 한 줄 인사이트가 이 스킬의 값이다. 표본 적은 동·층은
값이 흔들리니 참고용임을 덧붙인다.

## 정직성 체크리스트

- 동·층 프리미엄을 평형 보정 후 계산했는가(평형 큰 집이 많은 동이 그냥 비싸 보이는 착시 방지)?
- 표본 3건 미만 동·층은 제외했는가?
- 향을 데이터로 '추정'해 단정하지 않았는가(향은 제외가 기본)?
- 세대수·동수가 API 미신청으로 비었다면, 그 사실을 리포트와 답변에 명시했는가?
