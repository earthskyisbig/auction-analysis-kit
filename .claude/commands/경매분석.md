# /경매분석 — 원샷 오케스트레이터

사용자가 준 조건(예: `수원 권선구 아파트 3억~10억 유찰1~3회 59~85㎡`)으로 5단계 파이프라인을 순서대로 실행한다.

> **지역 전체를 조건으로 걸러 통과 물건만 추리는** "3조건 퍼널 스크리닝"(세대수·연식·**실거래량 환금성**
> 하드필터 → 상위 N건 권리 → 비교)이 필요하면 `auction-screening` 스킬 또는 로컬 웹앱(`webapp/`)을 쓴다.

## 실행 순서

1. **조건 파싱** — 지역→관할법원 매핑(court-search 표 참고), 용도·가격·면적·유찰 범위 추출.
   빠진 값은 합리적 기본값(입찰기간 --bid-days 180)으로 채우고 사용자에게 무엇을 가정했는지 알린다.

2. **① 크롤링** — `court-search` 스킬로 `collect_api.py` 실행 → CSV.
   정합성 검증(수집==totalCnt) 통과 확인. 결과 목록을 표로 보여주고 **분석할 물건을 고르게 한다**(또는 상위 후보 자동 추천).
   - **"경기도" 등 도(道) 전역**이면 관할 법원이 여러 개다 → court-search 표의 해당 법원들을 **각각 실행해 CSV 합침**(dedup: 사건번호+소재지). 지원은 **단축명**(성남지원 등)으로.
   - **경매 검색 API에 없는 조건(세대수·연식·동수 등)** 은 여기서 못 거른다 → 크롤링 후 `apt-value/fetch_complex.py`(또는 시도목록 배치 매칭)로 **세대수·준공연도를 붙여 사후필터**한다. 예: "500세대↑ & 2005년↑". 미매칭 단지는 "확인불가"로 분리(소규모로 단정 금지).

3. **② 권리분석** — 선택 물건에 `rights-analysis` 스킬로 `analyze_case.py` 실행.
   말소기준·임차인·인수보증금 판정. 인수 위험 있으면 사용자에게 먼저 경고.

4. **③ 입지분석** — `location-metrics` 스킬로 정량 4축(교통·직주·학군·인프라) 계산 →
   `location-analyst` 에이전트로 공급물량·호재 조사·검증 → 6축 종합등급(S~D).

5. **④ 수익성** — `profit-analysis` 스킬: real-estate MCP로 동일단지 실거래 시세 확정 →
   (아파트면 `apt-value`의 `fetch_complex.py`로 단지 스펙: 연식·세대수·동수·최고층 보강) →
   낙찰가 시나리오별 8대 비용 손익표 + 권장 낙찰상한.

6. **⑤ 보고서** — `report-builder` 스킬로 표준 HTML 보고서 생성(입지 레이더 포함).
   원하면 `auction-reports` 저장소로 배포(push → GitHub Pages).

## 원칙
- **각 단계 후 결과를 요약해 보여주고 다음 단계로 진행할지 확인**(특히 물건 선택·배포).
- 숫자 계산은 스크립트/규칙 기반으로. 추정은 "추정"이라 명시.
- 여러 물건을 분석했으면 마지막에 **비교표 보고서**도 제안.
- 모든 보고서에 8대 비용·면책·분석 메트릭 포함(report-builder 규칙).

## 최소 예시
```
/경매분석 양주시 아파트 85㎡이하 유찰1~2회 1억~3억
```
→ 의정부지방법원으로 크롤링 → 후보 표 → 물건 선택 → 권리·수익 → 보고서.
